# 开发说明

给以后改代码的人（包括以后的自己）看：项目怎么分层、一条消息怎么走、东西放在哪、要加功能该改哪几个地方。

## 1. 分层

```
cli.py · app.py · wizard.py      入口：命令行、运行时装配、配置向导
web/                             小屋（网页后端 + 单文件前端）
chat/                            群聊主流程：GroupChat 和它的各个部分
memory/                          她记得的东西
brain.py · persona.py            人设 + 大模型 + 数据库 + 她自己的一天
llm/ · wechat/                   对外的两个接口：大模型、微信（读本地库收、窗口操作发）
onebot.py                        程序内部统一的消息段格式和工具（沿用 OneBot 11；chat/ 用它）
core/                            配置、密钥、存储、文字消毒、作息时段、小工具
eval/                            回放和评审（离线工具，不在聊天主流程里）
```

**依赖只能往下**：`core` 不 import 任何业务模块；`llm/`、`qq/`、`wechat/` 只用 `core`；`memory/` 不 import `chat/`；`chat/` 可以用下面所有层；只有入口层和 `web/` 会把 `chat/` 装起来。新代码放进去之前先想清楚它属于哪一层。

## 2. 一条群消息走过的路

```
微信本地库 ──每秒看一眼──▶ wechat/bot.py  WeChatBot._poll_blocking → 转成 OneBot 格式的事件 → handlers
   ▶ chat/ingest.py   on_event：去重、消毒（core/safety.py）、记进 qq_group_messages、心情、表情包、复读；凑一批
   ▶ chat/speak.py    _after_wait：等连发说完 → plan.batch_features → gate.likelihood / threshold_ex → plan.decide
                      （13.0 差一点到阈值时 quick_judge 问便宜模型“说 / 等 / 不”；21.0 刚过阈值一点点也问一次）
   ▶ agent/mixin.py   agent_think：判断层决定要不要查 → 研究员（agent/loop.py + tools.py）→ 简报 v3 → brief_block
   ▶ chat/prompt.py   build_messages：system（不变的人设 → 一天才变的 → 一批才变的）+ user（每次都变的）
   ▶ llm/client.py    按 routes.chat 依次试，限流 / 出错换下一个
   ▶ chat/prompt.py   parse_plan_text：计划 JSON（说 / 不说 / 点表情、回哪条、几种说法、21.0 九问自评 appraise）
   ▶ chat/speak.py    appraise_verdict：说 / 不说 / 重写 / 等等（进 st.pitch，idle_tick 里 pitch_tick 再判）
   ▶ chat/speak.py    13.0 想好了还没发、群里来了新消息：带上新消息重新想（最多 rethink_max 次）
   ▶ chat/quality.py  质检、多选一、错别字；social.hard_issues 四条硬底线；_check_numbers 数字和重大说法对简报
   ▶ wechat/bot.py    send_group → wechat/wxui.py 粘贴发送 → 在库里看到自己那条才算发出去
   ▶ chat/feedback.py 5 分钟后看有没有人接（qq_reply_effect），每晚用这些数据重新拟合门控
```

空闲时 `app.py` 每分钟调一次 `GroupChat.idle_tick`（chat/idle.py）：冒泡、早上补回、整理（memory/digest.py）；每天早上 5 点以后备份数据库、跑一次每晚的活（chat/feedback.py 的 `nightly`）。

## 3. GroupChat 是怎么拼起来的

`chat/group.py` 里的 `GroupChat` 只做装配，活都在 Mixin 里（一个文件一件事）：

| Mixin | 文件 | 管什么 |
| --- | --- | --- |
| IngestMixin | chat/ingest.py | 收消息、补消息、记录 |
| SpeakMixin | chat/speak.py | 判断、说话、复读、点表情、回复延迟 |
| IdleMixin | chat/idle.py | 冒泡、早上补回、戳回去、改签名 |
| FeedbackMixin | chat/feedback.py | 说完的效果、回复节奏、每晚的活 |
| LifeMixin | chat/life.py | 她此刻在干嘛、感兴趣的话题 |
| PromptMixin | chat/prompt.py | 提示词 |
| PeopleMixin | memory/people.py | 群友：画像、别名、成员列表 |
| DigestMixin | memory/digest.py | 整理：群里的事和梗、画像、群日报 |
| StyleMixin | memory/style.py | 13.0 说话指纹、她自己的风格审计、画像的历史版本（每晚统计，不调大模型） |
| GrowMixin | chat/grow.py | 熟悉度、约好的事、提醒、生日节日、天气、分享、每月“我是怎样的人” |
| InsightMixin | chat/insight.py | 16.0 关系网、关系色彩、相处经验、谁刚回来、今天状态、小判断器 |
| HumaneMixin | chat/humane.py | 19.1 搭话（含 21.0.1 回答她问大家的问题）、今天说过的、相处说明书、像人的周指标 |
| AgentMixin | agent/mixin.py | 19.0 判断层 + 研究员、21.0 类型力度、简报 v3、重大消息反搜、事实账本 |
| FeedMixin | chat/feed.py | 20.2 “刷到的”：兴趣表、候选池、按事件去重 |
| EvalMixin | eval/weekly.py | 每周评测、定向测试、问答一致、附和测试、九问统计 |
| SocialMixin | chat/social.py | 21.0 九问自评记录、等等队列、擦边再问、人卡、四条硬底线 |

Mixin 之间只通过 `self` 上这些共用的东西协作（都在 `GroupChat.__init__` 里建好）：

- `cfg`（配置）、`brain`（人设 / 大模型 / 数据库 / 现在几点）、`ob`（微信：wechat/bot.py 的 WeChatBot，长得和 OneBot 客户端一样）、`db`（`core/store.py` 的 Store）
- `g`：群聊设置（`chat/settings.py` 的默认值 ← config.yaml 的 `wechat.group` ← 小屋里调过的）
- `state`：每个群的运行时状态（`chat/state.py` 的 GroupState，用 `self._st(gid)` 取）
- 组件：`gate`（门控日志）、`learner`、`memory`（事实和召回）、`stickers`、`tracer`、`lore`、`mood`、`detector`

**判断和解析尽量写成纯函数**放在 `chat/plan.py`（不碰数据库、不调大模型），Mixin 里只做“取数据 → 调纯函数 → 存结果”。纯函数最好测。

## 4. 数据

一个 SQLite 文件 `data/group.db`（WAL 模式）。**每个模块在自己文件里写 `SCHEMA`，启动时建表**：

| 表 | 文件 |
| --- | --- |
| kv（键值） | core/store.py |
| qq_group_messages | chat/group.py |
| qq_people、qq_profiles | memory/people.py |
| qq_reply_effect | chat/feedback.py |
| qq_gate_log | chat/gate.py |
| qq_trace、qq_pairs、qq_prompt | chat/trace.py |
| qq_facts、qq_embed | memory/facts.py |
| qq_expressions、qq_jargon | memory/learn.py |
| qq_lore | memory/lore.py |
| qq_stickers | memory/stickers.py |
| qq_profile_versions | memory/style.py |

kv 里的键按前缀分：`qq_*_{群号}` 是每个群的（`qq_mood_`、`qq_night_`、`qq_members_`、`qq_group_notes_`……），`life_{日期}` 是她每天的安排，`llm_stats_{日期}` 是调用统计，`web_overrides` 是小屋里调过的开关（全局），`web_overrides_g{群号}` 是只给某个群调的（盖在全局上面；代码里用 `self.gk(gid)` 读这个群实际用的值，`self.g` 是全局的），`migr_*` 是做过的数据升级。

**老用户的数据要一直能用**：只加表、加列，不改已有列的意思。加列用 `core/store.py` 的 `ensure_columns(conn, 表, {列: 类型和默认值})`；要搬数据的升级写成一次性的（做完在 kv 里记一个 `migr_*`，参考 `GroupChat._migrate_20`）。

## 5. 要加东西改哪里

| 想加 | 改哪里 |
| --- | --- |
| 一个命令（`python run.py xxx`） | `aigroup/cli.py`：写 `cmd_xxx(argv) -> int`，在 `COMMANDS` 里登记一行；要双击用的话在 `scripts/` 放个 `.bat`（照着 `scripts/people.bat` 抄） |
| 一个群聊设置 | `chat/settings.py` 的 `DEFAULTS` 加一行（带注释）；想让用户在配置文件里看到，也写进 `config.example.yaml` 的 `wechat.group`（值要一样，`test_settings_in_sync` 会检查）；代码里 `self.g["名字"]` |
| 小屋里能调的开关 | 再在 `chat/settings.py` 的 `KNOBS` 加一行（标签、类型、范围、说明）；页面上分组在 `web/page.html` 搜 `回复节奏（像真人）` |
| 一张表 / 一列 | 表：在负责它的模块里的 `SCHEMA` 加；列：`ensure_columns`；记得更新上面的表格 |
| 提示词里的一块内容 | `chat/prompt.py` 的 `build_messages`：先想好它多久变一次——一直不变的放 system 最前面，每次都变的放 user（DeepSeek 前缀缓存按这个省钱） |
| 一种新的大模型用途 | `self.brain.llm.chat(..., role="新用途")`；没配 `llm.routes.新用途` 时退回 chat（memory / night 先退回 helper），规则在 `llm/client.py` 的 `_chain` |
| 每晚跑一次的活 | 写成 GroupChat 上的方法，在 `chat/feedback.py` 的 `nightly` 里的名单加上名字 |
| 小屋的一个接口 | `web/server.py`：在 `GroupHome.app()` 里登记路由、写 handler；前端在 `web/page.html` |
| 一个新的 Mixin | 新文件 `chat/xxx.py` 写 `class XxxMixin`，在 `chat/group.py` 的 `GroupChat(...)` 里加上，并更新上面的 Mixin 表 |

## 6. 测试

```bash
python -m pytest        # 配置在 pyproject.toml：只跑 tests/
ruff check .            # 没用的 import、未定义的名字、import 顺序
```

- 测试按功能分文件：`test_plan`（纯函数）、`test_gate`、`test_speak`、`test_ingest`、`test_idle`、`test_people`、`test_memory`、`test_quality`、`test_eval`、`test_llm`、`test_web`、`test_app`、`test_llm_custom`、`test_wechat`（接入：解密、密钥、解析、收发闭环）、`test_wechat_v2`（补消息、重连、限速、小表情）、`test_wechat_v21`（复查修的：不丢消息、确认晚到、同名群、口令派生、分块读、副本目录）。
- 共用的假对象在 `tests/conftest.py`：`FakeLLM`（按提示词里的关键字回话）、`OB`（假的 OneBot，记下发了什么）、`_gc`（建一个 GroupChat）、`_msg`（造一条群消息）、`_run`（喂消息并等后台任务跑完）。
- 测试不联网、不碰你自己的数据。注意 `load_config` 会合并项目根目录的 `config.llm.yaml`（你电脑上有），要测“没配接口”时在测试里把 `c["llm"]` 清空。

## 7. 发布前

1. `python -m pytest` 和 `ruff check .` 都过。
2. 改 `aigroup/__init__.py` 的 `__version__`，在 `CHANGELOG.md` 写一段。
3. **仓库里只放通用的东西**：自己的群 id、微信号、群友的名字 / 外号 / 真名、群里的梗、自己的大模型接口和 Key 都不能进仓库（它们在 `config.yaml`、`config.llm.yaml`、`.env`、`data/`，都在 `.gitignore` 里）。示例和测试里用通用名字（小王、阿杰、老张）。推送前搜一遍自己的群 id（xxx@chatroom）、wxid_、`ghp_`、`sk-`；`data/wechat/`（密钥、解密的库副本）绝不能进仓库。
4. 不预置任何大模型接口：`config.example.yaml` 的 `llm.profiles` 保持空的，用户自己加。

## 8. 微信接入（wechat/）

| 文件 | 管什么 |
| --- | --- |
| crypto.py | SQLCipher 4 的一页：4096 字节，页尾 80 字节 = IV 16 + HMAC-SHA512 64；HMAC 密钥 = PBKDF2-SHA512(密钥, salt^0x3a, 2 次)；第 1 页前 16 字节是 salt |
| dbview.py | 加密库 → 明文副本：主库按页尾 HMAC 只解密变了的页；wal 只套“已提交”的帧（salt、校验和、每页 HMAC 都对），wal 重置（salt 变了）先把盖上去的页揭掉；副本文件头改成非 WAL，immutable 只读打开 |
| keys.py | 拿密钥（只读 ReadProcessMemory）：缓存 data/wechat/keys.json → Config.Cipher（异或掩码，偏移放宽扫描）→ 明文 x'…' → 口令派生（PBKDF2 256000）→ --deep（numpy + 多进程，不挑版本）。每个候选都用第 1 页 HMAC 验过才用 |
| wxdb.py | contact.db（contact / chat_room.ext_buffer 群名片 / chatroom_member）、message_N.db（Msg_md5(会话)、Name2Id、local_type 低 32 位是类型、zstd、“wxid:\\n”前缀、source 里的 atuserlist、49/57 引用的 svrid、47 表情、拍一拍） |
| wxui.py | Windows 窗口操作：单独聊天窗口（标题 = 群名）→ 切前台 → 点输入框 → Ctrl+A / Ctrl+V → 回车 → 还原前台和剪贴板；没有单独窗口时默认不发（search_fallback 打开才 Ctrl+F 搜群名，一次没核对上就停用）；等你停手、每次按键前确认前台、锁屏不发 |
| bot.py | WeChatBot：对 chat/ 装成 OneBot（handlers、on_connect、send_group、call）。wxid ↔ 整数编号（data/wechat/ids.db，从 10001 起）；get_group_msg_history / get_group_member_list 从库里取；发完在库里看到自己那条才算成功；限速；微信关了又开；旧消息交给 on_backlog；自己号在别处说的交给 on_self_message |
| diag.py | wxdiag / wxkeys / wxsend / wxtail |

**微信做不到的**（bot.call 直接报“不支持”，chat/ 里都有兜底）：点表情（`can_react = False`，提示词里也不给这个选项）、引用回复（reply 段丢掉）、拍一拍回去、改签名、AI 语音。`chat/settings.py` 里这几项默认都关了，也从小屋开关里拿掉了。

**历史遗留**：这套群聊大脑最早写给 QQ 群（[ai-life](https://github.com/star031104/ai-life) 里的 QQ 群版），所以数据库表名是 `qq_` 开头、代码里还有一些 `channel == "qq"` 的分支、内部消息用 OneBot 11 的消息段格式。这个仓库只跑微信（`aigroup/core/config.py` 的渠道固定是 `wechat`），这些分支不会走到；改的时候不用管它们，也别随手改表名（老数据会读不到）。

**测试**：tests/wxfake.py 用 sqlite + 自己加密造出和微信一样格式的库（主库 + wal，保留区 80 字节），FakeAccount 是一个假的账号目录（联系人、群、群名片、消息分片）；不需要真微信、不需要 Windows。Windows 专用的 ctypes 代码（wxui、keys 的读内存）测不到，改的时候格外小心，最好让用户跑一遍 `python run.py wxdiag`。

**发消息的安全规则（改 wxui / bot 时别破坏）**：只认单独窗口（标题 = 群名，同名 / 没名字不发）；每次按键前前台必须正好是那个窗口（GA_ROOT）；用户在用键鼠就等，等不到就放弃；剪贴板所有格式原样还原；发完必须在库里看到自己那条才算成功；搜索方式默认关。
解密副本放 data/wechat/cache/<账号>/p<进程号>/，目录里的 lock 文件被进程一直锁着，别的进程靠它判断能不能清掉。
